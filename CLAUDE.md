# BenPlate

A full-stack template: React + TanStack Router (`apps/web`), Hono + oRPC (`apps/server`, `packages/contract`, `packages/api`), Better Auth (`packages/auth`), and a Drizzle schema with Kysely queries on Postgres (`packages/db`). The [README](README.md) explains the setup. These are the rules.

## Database

- Define tables with `snakeCase.table`, never `pgTable`. Defaults are SQL only (`.default()`, `.defaultNow()`), never `$defaultFn` or `$onUpdate`: Kysely runs the queries, so Drizzle's runtime hooks never fire. Keep column names free of digits and acronym runs.
- Kysely's types live in `packages/db/src/generated/db.ts`, generated by kysely-codegen from the local database. Never edit it: `pnpm db:push` and `pnpm db:migrate` regenerate it (`pnpm db:codegen` alone), and it is committed with the migration.
- A fixed set of values is a `pgEnum`, like `planet_type`, never `t.text({ enum })`. A migration can't use an enum value added in the same deploy.
- Every table has `id: t.integer().primaryKey().generatedByDefaultAsIdentity()`. The database generates ids: inserts leave `id` out. Join tables use a composite primary key of their two foreign keys instead.
- The integer `id` is private: joins and foreign keys use it, the API never exposes it. A table whose rows clients address also has `publicId: t.text().notNull().unique("<table>_public_id_unique")`, filled with `newPublicId(prefix)` from `@benplate/db` on every insert, like `planets`. Each resource has a short prefix (`planetIdPrefix = "pl"`) defined once in its contract file. The API, URLs and route params (`$publicId`) use only `publicId`.
- Foreign keys are `t.integer()`, except to `user` (`t.text()`). Every table spreads `...timestamps` (`schema/columns.ts`) and gets an `updated_at` trigger in its own custom migration, like `planets_updated_at`.
- Name unique constraints explicitly: `.unique("<table>_<column>_unique")`. Always pass that name to `isUniqueViolation(error, constraint)`, so only that constraint maps to `CONFLICT` and any other violation stays a 500.
- Auth tables (`schema/auth.ts`) follow the same rules, except for ids: they keep Better Auth's stock random `text` ids, which it generates itself and which are safe to expose, so they need no `publicId`. To add a Better Auth plugin, copy its tables and fields from the plugin's docs page into the schema and generate a migration. The server checks the auth schema at startup and refuses to start on a mismatch.
- Always pass `--name` to `pnpm db:generate` (`--custom --name` for hand-written SQL). Never edit a migration that has been deployed; add a new one. See [Schema changes](README.md#schema-changes).

## API

- Routes that need a signed-in user use `authedContract` in the contract and `protectedProcedure` in the router, which sets `context.session`. Public routes use `oc` and `os`, and never look up the session.
- The contract (`packages/contract`) ships to the browser: it imports only oRPC and Valibot, never `@benplate/db` or Drizzle (no `drizzle-orm/valibot`). Write its schemas by hand. Output schemas list exactly the fields clients see, with types only (`publicId: v.string()`, never `id`); input schemas carry the validation rules (`publicId: publicIdSchema(planetIdPrefix)`). See [Adding a resource](README.md#adding-a-resource).
- Name procedures after what they promise: `get` returns one record by id or throws `NOT_FOUND`; `list` returns a collection, possibly empty. Query options in the web app take the procedure's name (`getPlanetQueryOptions` for `planet.get`).
- Declare expected errors in the contract (`.errors({ NOT_FOUND: {} })`) and throw them with `errors.NOT_FOUND()`. Map database errors to them in the handler.

## Web

- Forms use Formisch (`@formisch/react`), never TanStack Form. They validate with the contract's own schemas, exported from `@benplate/contract`, and map API errors to fields with `setErrors`.
- Read the session through `sessionQueryOptions` and use Better Auth's client through `authClient` (`apps/web/src/utils/auth.ts`).
- Route files (`src/routes/`) are `.ts` and only declare the route (`context`, `loader`, `beforeLoad`, `validateSearch`, `component`). The page component lives in `src/features/<feature>/`, is imported as `component`, and reads its route through `getRouteApi("<route id>")`, never by importing a route file.
- Routes own their data: `context` builds the query options (named after the procedure, e.g. `listPlanetsQueryOptions`), `loader` prefetches them, and the page passes the same options from the route context to `useSuspenseQuery`; it never builds its own. Search params that change the data go through `loaderDeps`. Loaders turn the API's `NOT_FOUND` into `notFound()`.
- Routes that need a signed-in user live under `routes/_app/`; everything else under `routes/(public)/`. See [Web routes](README.md#web-routes).
- Components are `const` arrow functions (`packages/ui` keeps shadcn's `function` style). Keep `no-use-before-define` off: tsc already rejects a value read before its declaration (TS2448).

## Server

- Read `process.env` only in `apps/server/src/env.ts`.
- Log through `context.log` in the API (`context.log.set({ … })` adds to the request's wide event) and through `log` from `apps/server/src/logger.ts` elsewhere. Never use `console`. See [Logging](README.md#logging).

## Before you finish

Run `pnpm fix`, then `pnpm check` (sherif, oxlint, oxfmt and tsc through uncheck, then knip). It must pass.
